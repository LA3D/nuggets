# Authoring workflow

## Intake

Capture:

- meeting date, audience, duration, and purpose;
- the decision, discussion, or learning outcome;
- approved papers, links, screenshots, data, and vault notes;
- confidentiality or publication constraints.

Summarize the source set and flag missing provenance before drafting.

## Narrative checkpoint

Offer a short story arc such as context → evidence → implications → discussion. For each proposed slide, give its purpose and main claim. Ask the user to approve or revise the arc before expanding it.

## Drafting

Scaffold a new directory, replace all template placeholders, and keep metadata truthful. Prefer short headings that make a claim. Use columns sparingly, limit text density, and reserve detail for notes. Keep external links descriptive.

## Review loop

1. Render only the working deck.
2. Inspect the title, typical content, densest, image-heavy, and final slides.
3. Repair overflow, small type, poor contrast, broken assets, and unclear provenance.
4. Review narrative flow and discussion questions with the user.
5. Repeat until the deck is ready.

## Publication readiness

Before any public-site update, verify the final title/date, remove draft placeholders, confirm asset permissions, validate citations and links, and ask whether the deck should enter the public listing. Treat rendering into `docs/`, committing, pushing, and publishing as separately authorized actions.
